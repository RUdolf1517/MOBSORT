# Mobilization Sort

## Аннотация

Mobilization Sort — интерактивная консольная реализация поэтапной сортировки массива. Исходные элементы случайно распределяются по последовательным группам, каждая группа отдельно сортируется и затем объединяется с ранее упорядоченной формацией. Программа предоставляет пошаговую визуализацию состояний алгоритма и событийную звуковую индикацию набора элементов. Реализация написана на Rust; текстовый интерфейс использует Ratatui и Crossterm, звуковая подсистема — CPAL.

## 1. Формальная модель

Пусть входной массив содержит \(n\) целочисленных значений \(A=(a_0,\ldots,a_{n-1})\). Каждому элементу сопоставляется идентификатор исходной позиции, поэтому элемент представлен парой \((a_i,i)\). Сравнение выполняется лексикографически по значению и идентификатору; это задаёт однозначный порядок для повторяющихся значений.

Состояние алгоритма включает резерв необработанных элементов и отсортированную формацию. Начальная формация пуста, а резерв содержит все элементы входа. Заданы пять кумулятивных уровней охвата исходного массива: 10%, 25%, 50%, 75% и 100%. Для уровня \(p_j\) размер целевой формации определяется как

\[
t_j=\min\left(n,\left\lceil\frac{p_j n}{100}\right\rceil\right).
\]

На волне \(j\) из резерва без возвращения выбирается \(t_j-|F_{j-1}|\) новых элементов, где \(F_{j-1}\) — формация после предыдущей завершённой волны. Выбранная группа сортируется инкрементальной стабильной сортировкой слиянием, после чего сливается с уже отсортированной формацией. Выбор состава группы псевдослучаен; генератор использует системный источник случайности Rust и не предоставляет параметр фиксированного seed.

Если соседние уровни для малого массива задают одинаковую целевую численность, соответствующая пустая волна пропускается. Для пустого массива алгоритм завершается без набора элементов.

Для \(n=50\) целевые размеры формации равны 5, 13, 25, 38 и 50. Следовательно, размеры новых групп составляют соответственно **5, 8, 12, 13 и 12** элементов.

## 2. Корректность и вычислительная сложность

После завершения каждой непустой волны формация упорядочена по парам \((a_i,i)\), а вместе с резервом содержит каждую исходную пару ровно один раз. Сортировка выбранной группы сохраняет это свойство; слияние двух упорядоченных последовательностей формирует упорядоченную формацию. Реализация проверяет эти условия после завершения волны. На последнем уровне \(t_5=n\), поэтому резерв пуст, а формация содержит весь вход в неубывающем порядке.

Для фиксированного числа волн (пять) суммарная стоимость сортировок групп составляет \(O(n\log n)\), а суммарный объём слияний и подготовки выборок — \(O(n)\) с точностью до постоянного множителя числа волн. Таким образом, временная сложность реализации — \(O(n\log n)\), дополнительная память — \(O(n)\). Сортировка группы и слияние выполняются инкрементально, что позволяет отображать промежуточные перемещения без блокирующего вычислительного этапа.

## 3. Визуализация и звуковая индикация

Интерфейс показывает три области: отсортированную формацию, мобилизованный отряд и резерв. Формация отображается зелёным цветом, отряд — жёлтым, резерв — голубым. Перемещаемый элемент на короткое время выделяется красным; после завершения перемещения он отображается цветом соответствующей области. В частности, набранный в мобилизованный отряд элемент после переходного красного выделения отображается жёлтым.

Начальный режим визуализации автоматически масштабирует массив под ширину терминала. Если элементы перестают помещаться по отдельности, соседние значения объединяются в экранные ячейки с отображением их диапазона; число элементов, представленных одной ячейкой, указывается в слое. `F` возвращает обзор всего массива, `D` включает детальный просмотр, а клавиши прокрутки автоматически переключают в детальный режим.

Звуковая последовательность основана на мелодии Государственного гимна Российской Федерации и синтезируется программно. **Нота запускается исключительно событием набора нового элемента из резерва в мобилизованный отряд.** При отсутствии такого события звук не инициируется. Запуск приложения, ожидание, отрисовка, пауза, сортировка элементов внутри отряда и слияние с формацией сами по себе звука не создают. Для одного события набора воспроизводится одна очередная нота; последовательность продолжается между волнами. Очереди фонового воспроизведения нет: последующие ноты не проигрываются без новых событий набора. Отключение звука прекращает текущую ноту; при отсутствии аудиоустройства сортировка остаётся доступна без звука.

## 4. Сборка и запуск

Требуется стабильная версия Rust. Запуск с аудиоподдержкой:

```sh
cargo run --release
```

Сборка без аудиоподдержки:

```sh
cargo run --release --no-default-features
```

При включённой аудиоподдержке доступность сборки зависит от системных требований CPAL и установленного аудиоустройства. Например, на Linux для CPAL может потребоваться ALSA development package. Сборка без стандартной feature `audio` не требует CPAL и сохраняет функциональность сортировки и визуализации.

## 5. Входные данные

Программа поддерживает следующие источники:

- **Random** — генерация массива; значения по умолчанию: 50 элементов из диапазона 1…100. Количество и границы диапазона задаются в форме.
- **Manual** — ввод целых чисел, разделённых пробелами, запятыми или точками с запятой.
- **File** — чтение чисел из текстового файла TXT/CSV. Поддерживаются те же разделители; часть строки после символа `#` трактуется как комментарий.

Допустимый тип значения — `i64`; максимальная длина массива — 3000 элементов. Поддерживаются отрицательные и повторяющиеся числа.

| Клавиша | Функция |

| `↑` / `↓`, `Enter` | Выбор источника данных и подтверждение |
| `Space` | Приостановка или продолжение вычисления |
| `R` | Повторный запуск на том же массиве |

## 7. Зависимости и распространение

Прямые зависимости Cargo: `ratatui`, `crossterm`, `rand`; `cpal` подключается необязательной feature `audio`, включённой по умолчанию. Workflow `.github/workflows/release.yml` формирует релизные сборки для Windows x86_64 и macOS (Intel и Apple Silicon), а также файл SHA-256 контрольных сумм.

## 8. Установка и обновление через Homebrew

Формула `mobilization-sort` размещена в tap `RUdolf1517/MOBSORT` (файл `Formula/mobilization-sort.rb`). Tap привязан к репозиторию и не создаётся заново для каждого релиза. При выпуске новой версии обновляются номер версии и тег исходного кода в той же формуле.

Первичное подключение tap и установка:

```sh
brew tap RUdolf1517/MOBSORT https://github.com/RUdolf1517/MOBSORT.git
brew install mobilization-sort
```

Обновление уже установленной программы:

```sh
brew update
brew upgrade rudolf1517/mobsort/mobilization-sort
```

Перед обновлением Homebrew должен синхронизировать локальную копию tap; иначе команда `brew upgrade` может сообщать о ранее установленном номере версии, даже если новый GitHub Release уже опубликован.
